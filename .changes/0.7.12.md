## 0.7.12 - 2026-11-20
### Added
* A bundle now warns once at boot, in one `[CONFIG][loadBundleConfig]` line, about each route URL segment that holds a placeholder followed by a character other than a letter, a digit or an underscore, such as `"url": "/:lang-code/home"`. A placeholder's name is its letters, digits and underscores: except on a DELETE route with `requirements`, gina reads `:lang-code` as the placeholder `:lang`, so a binding under `lang-code` is never filled, the route matches only when its `param` also binds `lang`, and a `culturePrefix` route that binds `"culture": ":lang-code"` reads no culture from the URL. Name each placeholder with letters, digits and underscores (`:lang_code`); nothing is rewritten. Pick it up with a bundle restart. (#B1143)
* A bundle now warns once at boot, in one `[CONFIG][loadBundleConfig]` line, about each route URL segment that holds text before a placeholder its route binds, such as `"url": "/articles/page:number"`. gina neither compares nor removes that text: the placeholder takes the whole segment, so such a route also matches `/articles/42`, reads `page3` from `/articles/page3`, and a requirement tests the whole segment (a DELETE route with `requirements` compares the segment as written). Put the fixed text in a segment of its own (`/articles/page/:number`); nothing is rewritten. The routing guide said such a route reads `3` from `/articles/page3`, which never held: the guide is corrected. Pick it up with a bundle restart. (#B646)
### Security
* Gina now requires `ws` `^8.23.0` in both manifests (it was `^8.22.0`). Up to 8.22.0, a peer that sent Ping frames and stopped reading made `ws` queue an automatic Pong for each one, without limit, until the process ran out of memory (advisory GHSA-37g9-w4hg-h9qr, every `ws` release from 8.0.0 before 8.23.0). 8.23.0 closes the connection once 60 automatic Pongs are waiting to be written (`maxPendingAutoPongs`). Gina loads `ws` for the Inspector agent WebSocket at `/_gina/agent`, which exists in dev mode and, outside dev, only when `settings.json` `inspector.agent.enabled` is true, where it then requires the agent key, and, through engine.io, for a bundle whose `settings.json` sets `ioServer.integrationMode` to `"attach"` (engine.io now runs on gina's `ws` too, #S25). Upgrading gina installs 8.23.0 or later; restart the bundle. (#S24)
* A bundle whose `settings.json` sets `ioServer.integrationMode` to `"attach"` now runs engine.io's WebSocket transport on gina's own `ws` (`^8.23.0`), unless its `ioServer` block names a `wsEngine`. engine.io pins its own `ws` range, below 8.23.0 in every 6.6.x release (`~8.21.0` in 6.6.9 to 6.6.11, the latest), so an install from the registry placed an older `ws` under engine.io that gina's `ws` range did not reach, and such a bundle stayed exposed to ws's advisory GHSA-37g9-w4hg-h9qr: a peer that sent Ping frames and stopped reading made `ws` queue an automatic Pong for each one until the process ran out of memory. A project whose own `package.json` overrides `ws` decides the version gina loads as well: raise such an override to `^8.23.0`. Upgrading gina installs `ws` 8.23.0 or later; restart the bundles in attach mode. (#S25)
* WebSocket over HTTP/2 (`app.onWebSocket()` and `method: "ws"` routes): a session now answers at most `maxPendingAutoPongs` Pings automatically (60 by default) while earlier Pongs are still waiting to be written, and resets the stream past that: the session closes with 1006. Before, a client that sent Ping frames and did not read the Pongs made the session queue every Pong, so memory grew until the process ran out of it. A session also no longer answers a Ping after it has sent its Close frame, and a close the peer leaves unanswered for the close timeout (5 s) now resets the stream instead of half-closing it, so data still queued at that moment is dropped. `param.wsOptions` (and `onWebSocket()`'s third argument) accepts `maxPendingAutoPongs`; `0` restores the unbounded behaviour. Only bundles serving WebSocket routes on Isaac with `http2Options.enableConnectProtocol: true` were affected. Restart the bundle. (#B1139)
* Isaac bundles whose `settings.json` sets `ioServer.integrationMode` to `"attach"`: Isaac's own upgrade listener, which hands engine.io the upgrades on paths other than engine.io's own (a bundle's push path, for instance), no longer hands it an upgrade on engine.io's own path (`/engine.io/` unless `ioServer.path` says otherwise), which engine.io's own listener already serves, nor any upgrade when the websocket transport is disabled, and it drops the socket if engine.io throws. The Inspector agent's upgrade listener (`/_gina/agent`, in dev mode or when the agent is enabled) likewise drops a socket that another listener has already upgraded. Before, a WebSocket request could throw inside one of these listeners and stop the bundle. Upgrades on other paths reach engine.io as before. Only bundles in attach mode were affected. Restart the bundle. (#B1140)
* Every bundle: the Inspector agent's upgrade listener (`/_gina/agent`) is attached to every bundle's server, so Node.js accepted every HTTP upgrade request, and an upgrade on any other path that no listener took was left open. Such a request is now answered as a plain request (Node.js 22.21 and later, 24.9 and later, when no other upgrade listener is attached) or closed after one second, as engine.io closes an upgrade nobody answered; on Bun, when another upgrade listener is attached, it is left to that listener. Restart the bundle. (#B1141)
