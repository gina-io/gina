## 0.7.14 - 2026-11-27
### Fixed
* The Inspector's Query tab no longer marks a Couchbase statement "no index — full bucket scan" (the red badge, counted in the "queries without index" banner) when its reads sit in subqueries. Couchbase plans a `LET` or `WITH` subquery, a correlated subquery and a nested subquery apart, and lists their plans beside the statement's own plan, which was the only plan the badge read. The badge now reports the indexes of every subquery plan as well, each index once; a subquery in a `FROM` clause was already reported, as Couchbase plans it inside the statement. A statement that reads no keyspace at all, such as `SELECT 1` or an `INSERT … VALUES`, now shows a green "no keyspace read" chip instead of the red badge; a plan holding any other operator keeps the previous reading. A bundle restart picks it up (#B1161)
* A cached page now answers each cross-origin caller with its own `Access-Control-Allow-Origin`. With `access-control-allow-origin` set to a comma-separated list in `server.response.header`, gina answers a request with its origin when the list holds it, and with none otherwise; a hit of the output cache answered with the value picked for the request that filled the entry instead, so a caller from another listed origin was refused by its browser, and an unlisted caller, or a request without `Origin`, received the first caller's origin. The same held for the bundle's own origin and for an empty configured value, which both answer with the request's origin. An entry no longer stores the header, and every hit computes it for its own request by the same rule as an uncached response, an entry stored by an earlier release included. A bundle restart picks it up (#B1104)
* A cached route's response now names, in `Vary`, the request headers its page depends on. The page follows the visitor's language (the `Accept-Language` header or the culture cookie) and, behind a proxy, the forwarded host, scheme and prefix, and it is sent with `Cache-Control: <visibility>, max-age=<seconds>`; it carried no `Vary`, so a browser kept the copy it held for the page's whole `max-age` after the visitor's language changed. The response that fills a cache entry and every hit now append `Accept-Language, Cookie, X-Forwarded-Host, X-Forwarded-Proto, X-Forwarded-Prefix` to `Vary`, after the names it already carries (a configured `vary: Origin` stays first), and the entry stores them. `Vary: Cookie` makes a browser fetch the page again after any cookie changes, and most shared caches do not reuse a response that varies on `Cookie`. A bundle restart picks it up (#B1164)
* A bundle that enables `server.rateLimit` or `server.idempotency` no longer refuses to boot with "[kv] not configured": the engine resolves both policies when it starts, and the kv namespaces were installed only after the server started listening, so no bundle could enable either feature. The namespaces are now installed before the engine starts, and a kv configuration error now refuses the boot before the port is bound. A bundle restart picks it up (#B1165)
* A page served from the render cache on a rate-limited route no longer sends the `RateLimit` and `RateLimit-Policy` headers of the request that filled the entry: every hit answered later visitors, anonymous ones included, with that caller's remaining quota. A hit is answered before the rate-limit gate, so it is not counted, and it now carries neither header. A bundle restart picks it up (#B1105)
* A `//` inside a quoted value no longer breaks a JSON file read with comments: `requireJSON()` and `parseJSONWithComments()` cut each line at its first `//` unless the character before it was `:`, `"` or `\`, whether or not it sat in a quoted value, so a value holding a `//` that is not a URL (a path joined from a directory ending in `/`, such as `"/var/folders/…/T//gina"`) was cut and its file failed to parse, and a `//` comment after a URL value on the same line was kept. A `//` now starts a comment only outside a quoted value; a file that parsed before parses to the same value. A bundle restart picks it up (#B1170)
* A SQLite `.sql` method whose statement starts with `WITH`, `VALUES` or a `PRAGMA` that reads a value returns its rows: the connector read rows only from a statement starting with `SELECT` and ran every other one with `run()`, so those methods returned `{ changes: 0, lastInsertRowid: 0 }` with no error. It now asks each prepared statement once, when the bundle loads it, whether it returns rows: `columns()` on node:sqlite (from Node 22.16.0 and 23.11.0), `reader` on bun:sqlite, and the leading keyword where the statement offers neither. A method whose statement is `INSERT`, `UPDATE` or `DELETE … RETURNING` now returns the rows its `RETURNING` clause lists instead of the write's `{ changes, lastInsertRowid }`. A bundle restart picks it up (#B1169)
* `req.routing.method` reads the same upper-case method on every request to a route: the first request, matched by a scan of the routing rules, read it in upper case (`GET`), and every later one, answered from the route cache, in lower case (`get`), so code comparing it with `'GET'`, as the routing guide shows the field, matched on the first request only. A bundle restart picks it up (#B1171)
* The dev Inspector shows `no keyspace read` for a Couchbase `bulkInsert` and sends no `EXPLAIN`: with no query profile from the SDK, it ran an `EXPLAIN` of the statement as it logs it, by default the line `INSERT INTO <keyspace> (KEY, VALUE) -- N record(s) [values redacted]`, which the server rejects, so the badge read `N/A`; with `inspector.queries.captureValues` on, the `EXPLAIN` carried the record values and its cache entry kept them. A `bulkInsert` runs an `INSERT … VALUES … RETURNING`, which reads no keyspace. A bundle restart picks it up (#B1163)
* On a Bun whose bun:sqlite statements carry no `reader`, as on Bun 1.2.21, the SQLite connector asks each statement's `columnNames`, the column list bun:sqlite reports, whether it returns rows, so there too a `.sql` method whose statement is a `WITH` clause feeding a write returns `{ changes, lastInsertRowid }`, and one whose statement is `INSERT`, `UPDATE` or `DELETE … RETURNING` returns its rows. A bundle restart picks it up (#B1173)
* The dev Inspector no longer reports a Couchbase statement that reads from an expression, such as `SELECT RAW d.x FROM [ … ] AS d`, as a key lookup: Couchbase plans it as an `ExpressionScan`, which reads no keyspace, and the index badge showed the green `KV lookup (USE KEYS)` chip for it. `USE KEYS` (a `KeyScan`) keeps that chip; a statement whose only source is an expression shows `no keyspace read`, as `SELECT 1` does, and beside an index read it adds nothing. A `FROM` over an expression that feeds a `JOIN` or `NEST … ON KEYS` shows the red badge although it reads by key: the badge does not label a key-based join. A bundle restart picks it up (#B1162)
### Security
* A route's output cache (`cache` in `routing.json`) keyed a page on its URL alone, so the request that filled an entry decided what every later visitor of that URL got until the entry expired: its host in the absolute links and form actions `getUrl()` builds and in gina's client loader values, its webroot, and its language in the translated text and the validation labels. Where a bundle accepts a client's `Host` or `X-Forwarded-Host` (reached directly, or through a proxy that forwards them), a request carrying another host could fill an entry so that every visitor's links and form submissions went to that host. The key now also carries the request's forwarded scheme and host, its forwarded prefix and the culture its culture cookie or `Accept-Language` selects, compared as written (`fr` and `fr_FR` are two entries); an `fs` entry is stored under a directory named for them, and `GET /_gina/cache/stats` lists each entry's `variant`. A page is stored only when it was rendered with those values: a culture taken from a URL prefix, or set by a middleware, that the headers do not select is rendered each time. A script that pre-fills cached routes now fills only the entries for the host, scheme and language it sends, so make it send what your visitors send. Entries stored before the upgrade are not read after it; with a constant `GINA_CACHE_NAMESPACE`, `fs` files from before stay on disk until `gina cache:clear` removes them. Server-side: restart each bundle. Affected since 0.1.6 (#B1132)
* The rule that picks a response's `Access-Control-Allow-Origin` compiled regular expressions from the request: a value from the request's `Origin` (or, without one, its scheme and `Host`) that it never used, and, for an HTTP/1.1 request without an `Origin`, a pattern from its `Host` tested against a `Referer` that is always empty at that point. An `Origin` or `Host` that is not a valid pattern, or a request with no `Host` at all, made the rule throw. On a static file the throw stopped the bundle process; on a page, a 404 or a preflight the request was left unanswered. Through 0.7.13 every bundle ran the rule, whatever its configuration; in 0.7.14 a bundle runs it for a configured `access-control-allow-origin` name. The rule now compiles no pattern from the request: an HTTP/1.1 request without an `Origin` takes the bundle's configured scheme, a `{name@project}` token with no bundle configuration behind it is left as written, and a rule that throws (a configured value that is not a string) sends no `Access-Control-Allow-Origin` and logs the error instead of stopping the bundle. A bundle restart picks it up (#B1166)
* With `access-control-allow-origin` configured empty (each request gets its own origin back), the `{bundle@project}` token substitution meant for a configured value also ran on the request's own `Origin`, so `Origin: {api@myproject}` was answered with that bundle's configured hostname, or its scheme, host and port when it has none. A token is now resolved in a configured value only, and the request's origin is answered as it was received. A bundle restart picks it up (#B1167)
* gina compared a request's method with each rule's `method` by compiling the request's method as a regular expression. Over HTTP/1.1 Node answers a method it does not know with a 400 before the request reaches gina, but an HTTP/2 client can send any token as its method: `*` or `+` made the compile throw, so the request was never answered, and a method such as `.` matched every rule, so an action ran under a method its rule does not list, without its body; a long run of `.*` made the match backtrack for seconds, during which the bundle answered no other request. The method `__proto__` replaced the request object's prototype: the request went unanswered, and the bundle process stopped when its stream closed. A request whose method is not in Node's `http.METHODS` now gets a 501 (Not Implemented) before any rule is compared, and the method is matched as text; the methods Node lists match as before. A bundle restart picks it up (#B1168)
