## 0.7.2 - 2026-10-03
### Added
* Versioned asset URLs, so browsers can keep a bundle's scripts and stylesheets for a year: in production, the `<link>` and `<script>` tags gina writes from `templates.json` (and their HTTP/2 preload hints) end in `?v=` plus the first 10 hex characters of the file's SHA-384, and the statics gina serves answer `Cache-Control: public, max-age=31536000, immutable` when the token names the file's current bytes, `no-cache` for any other token, and exactly as before without one. The client routing table is fetched the same way, its token carried on gina's own script tag. A deploy that changes a file changes its URL, so a returning visitor fetches it once and no stale copy survives. On by default; `assetVersioningEnabled: false` in `templates.json > _common` keeps the plain URLs. Not versioned: dev mode, renders without a layout, `isExternalPlugin` scripts, hand-written tags. A front server that serves the statics, such as nginx, should send requests that carry a token to the bundle, which checks it (see the statics reference). Restart the bundle to pick it up; if your build copies `gina.min.js` into your own static files, rebuild that copy before the restart: an older copy compares script URLs exactly, so it can run a script twice when a popin or a swapped region includes a file the page loaded under its versioned URL. (#P48)
* The fast lane: a JSON route can skip the controller. Declare `"param": { "lane": "users", "control": "list" }` in `routing.json` and export `list` from the bundle's `lanes/users.js`: the function receives one context object and answers with `ctx.json()` or `ctx.error()`, with `ctx.params`, `ctx.body`, `ctx.session`, `ctx.getConfig()` and `ctx.hasRole()` at hand. Everything gina does before the router still runs (the request id, CORS, the security headers, maintenance mode, statics, body parsing, the route match and its requirements), and so does the bundle's own middleware, such as the session and CSRF layers; the access line, the metrics and the JSON error envelope are those of any route. Measured with one process serving the same JSON answer both ways: a median 0.39 times the CPU of the controller route, about 150 microseconds less per request. Lane routes are checked at boot, which refuses one that declares route middleware, `cache`, `negotiate`, `namespace` or `method: "ws"`, and, in this release, any gate (authorization, rate limit, idempotency, message validation, request DTO), including the implicit ones of `auth.requireAuthByDefault` and `server.rateLimit`. A lane module edit is picked up in dev mode; a routing change needs a restart. Opt-in: existing routes are unchanged, unless one already used a `param` key named `lane` for its own data. Restart the bundle to pick it up; nothing to re-bake. (#P49)
### Fixed
* Staged uploads: a file input's browser placeholder value (C:\fakepath\name) is no longer collected into the form-submit payload — a staged file input's data travels through its hidden fields, so the input is skipped from the payload while staying available for rule evaluation (#B725). A transport-level request failure (XHR status 0) now reports "the request did not complete" instead of "the request did not reach the server" — honest for a proxy 413 that arrives mid-send over HTTP/2 and for a navigation that aborts the request, both of which reached the server — resolved through an overridable label (gina.config.a11y.transportError) and tagged with a reason of unload or transport (#B724). Reported as gh#83 parts 1 and 2. Browser-bundled: rebuild bundles to pick it up.
* Staged uploads: a form submitted while one of its staged uploads is still uploading now waits for it, then sends once with the uploaded file's metadata, instead of posting the upload's still-empty hidden fields. While it waits the submit control keeps its busy state and the form's live region announces the wait once (overridable as gina.config.a11y.uploadPending, default "Waiting for the upload to finish…"); if an upload fails, the waiting submit is cancelled and nothing is sent. This covers every way a validator-bound form is submitted — the submit control, Enter, requestSubmit() and $forms[id].submit() — while a direct $forms[id].send(data) call, which carries its own payload, is not held (#B726, gh#83 part 3). Browser-bundled: rebuild bundles to pick it up.
* A page whose query string ends in the client routing table's path, such as `/web/?next=/_gina/assets/routing.json`, is answered by the page instead of the table: both engines now test the table on the URL's path only, as the other built-in endpoints have since 0.7.1. Restart the bundle. (#P48)
* A precompressed `.gz` file went out as `Content-Encoding: gz`, its file extension, which is not a content coding, so a client could not decode it: Chromium does not run such a script. In production gina now sends `Content-Encoding: gzip`, for a static's `.gz` copy (over HTTP/1.1) and for the routing table's `.gz` copy (isaac, both protocols); `.br` copies were already sent as `br`. With gina's order (brotli, then deflate, then gzip) the `.gz` copy goes only to a request that accepts gzip but neither brotli nor deflate, such as Go's HTTP client by default or a proxy or CDN set to ask the origin for gzip; browsers also send deflate and were not served it directly. Restart the bundle. (#B742)
* In production, the statics gina serves over HTTP/1.1 and the routing table on the isaac engine now carry `Vary: Accept-Encoding`, on the 200 and on the 304, so a shared cache no longer hands a brotli or gzip copy to a client that does not accept that coding. Every such static carries it, with a precompressed copy or not; a `vary` declared under `server.response.header` in the project's `env.json` is kept and now reaches the 304 too. HTTP/2 statics and dev mode are unchanged. Restart the bundle. (#B743)
* On a bundle serving HTTP/2, an error answered by gina's server-level error path (a 404 for a missing route, a 405, a 500) was counted by the Prometheus metrics as a `200` under `route="__no_route__"`: the answer goes out on the raw HTTP/2 stream, and the response object it bypasses kept its default status, which is what the metrics read when the response finishes. The response now carries the code it sends, so a 404 counts as `404` under `__not_found__`, as it already did over HTTP/1.1. Clients always received the right status. Restart the bundle. (#B749)
* Five places assigned `headersSent` on a response after sending it. `headersSent` is read-only on Node's response objects, so in these strict-mode files each assignment threw a `TypeError` after the client had its answer: with the nunjucks engine over HTTP/2, every rendered page logged an unhandled promise rejection; with a redis render cache over HTTP/2, the first request for each cached URL after a restart (or on a fresh replica) logged one and wrote no access-log line; `self.renderXML()` skipped its cleanup over HTTP/2 and, over HTTP/1.1, could call the action's `next()` after the response had ended. The assignments are gone. Restart the bundle. (#B750)
* The SQLite session store now reads its file path from `file`, as the SQLite job and kv stores already do. The sessions guide and the connectors reference showed a persistent store with its path in `database`, and that configuration stopped the boot: the model layer opens a connector for every connectors.json entry and reads `database` as a database name under the gina home, so it tried to open `<home>/<path>.sqlite`. The examples now use `file`, for a path and for `":memory:"`. A configuration that boots today behaves as before (`database` on its own is still read when `file` is unset), and with neither key the store keeps its default file, `~/.gina/sessions-<bundle>.db` (#D47).
* Staged uploads: choosing another file while the previous one is still uploading now stages the new file. The new selection was silently dropped while the input showed it, and the first upload then filled the form with the replaced file's metadata. The earlier request is now cancelled and settles through the `abort` event only, with no error and no on-error callback; it may already have reached your staging action, which can leave an unclaimed temporary file. A submit already waiting for the upload waits for the new one and sends its metadata (#B729). Browser-bundled: rebuild bundles to pick it up.
* Staged uploads: a file input inside a popin that was closed and reopened stages files again. After the reopen every selection threw `setAttribute is not a function` and sent no staging request, so the upload never ran and its on-success callback never fired. The input now builds a fresh upload form when the previous one left the page with the popin's content (#B733). Browser-bundled: rebuild bundles to pick it up.
* Popins: closing a popin through `gina.popin.close(name)` now tears down the forms it bound, as its close button and its own `close()` already did. The forms stayed registered against their removed markup, so after a reopen they were not bound again: their rules, their submit handling and their declared events were lost, and a staged upload in them sent nothing. This concerns a popin constructed with a validator (#B756). Browser-bundled: rebuild bundles to pick it up.
* Staged uploads: two forms on one page whose staged file inputs share a name without brackets (`name="doc"`) no longer share one upload form. The second form's upload filled the first form's hidden fields and left its own empty. Each form now gets its own upload form, whose id ends with the form id (`gina-upload-doc-<form id>`); a bracketed name keeps its id. Code that matched the old id literally should read the input's `data-gina-form-virtual` attribute instead (#B732). Browser-bundled: rebuild bundles to pick it up.
* Staged uploads: a failed staging request now reaches the `data-gina-form-upload-on-error` callback even when the input has no error element. Without one, the client threw before the error event and the callback, so neither ran, for an HTTP error and a transport failure alike; the message is now announced through the form's live region, and in dev mode a console warning names the missing element. The error element is also read from the file input's own `data-gina-form-upload-error` attribute (default `<id>-error`): it was taken from the form's last input, so a custom element was honoured only when the file input came last (#B731). Browser-bundled: rebuild bundles to pick it up.
### Security
* The staged-upload client layer rendered a staging request's error message with innerHTML, so a reverse-proxy or WAF HTML error page — or a server error that reflects request text such as a rejected upload filename — was parsed as live markup in the page. The upload error slot now builds the message with createElement and textContent, so a server error message is always rendered as text (#B727, gh#83 part 4). Browser-bundled: rebuild bundles to pick it up.
* Raised the `engine.io` dependency floor from `^6.6.7` to `^6.6.10`, the first release patched for GHSA-2gc4-cqfq-p2gv (CVE-2026-102599): on an existing session, a transport-upgrade request carrying a different or missing protocol revision could crash the process. Gina loads engine.io only for a bundle whose `settings.json` sets `ioServer.integrationMode` to `"attach"`; such a bundle was exposed when its install resolved engine.io 6.6.0 to 6.6.9 with transport upgrades allowed, which is the default. `^6.6.7` already let a fresh install resolve a patched release; with the new floor, an install of this version cannot resolve an affected one. Restart attach-mode bundles to load it (#S12).
